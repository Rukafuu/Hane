# Workspace attachments

The mission composer paperclip opens file/folder choices and a collapsible pasted-text option. The local API opens an OS dialog, returns only validated path metadata, and never reads content or changes the server default at selection time. Windows uses .NET OpenFileDialog/FolderBrowserDialog, macOS uses the built-in choose file/folder AppleScript dialog, and Linux uses Zenity in a graphical session. The dialog opens on the computer running the local Hane server, not a remote browser computer. Missing platform facilities produce an inline error. Dialog cancellation preserves the draft.

POST /api/workspace/select is covered by the existing host/origin/request and profile/session guards. It serializes dialogs, aborts the helper on client disconnect, caps lifetime at two minutes, and rechecks authentication after selection. Dialog scripts and argv are constant; request values are never interpolated into scripts. Existing resolver containment, canonical paths, plain scope limits and the secret policy also apply to selections, including selecting a sensitive directory as the root.

A file grants workspace.read for that exact relative path. A directory grants its subtree. The composer displays the name and read permission before send, passes the returned canonical workspaceRoot with the mission, and removes implicit grants with removed attachments. Manual grants remain separate and are deduplicated on send. A mission has one root: existing attachments and workspace permissions must be removed before changing to an unrelated root. Removing the last item retains the chosen root for subsequent selections but grants no access by itself. Sending resets that composer root. Per-agent capability checks still apply to the team preset. This selects live disk references, not copied/uploaded snapshots: later executions read the then-current permitted files through audited tools.

Validation: six focused tests cover constant native commands, root and scope mapping, sensitive-file refusals, HTTP cancellation/origin guards, dialog concurrency/session revocation, grant removal and API payloads. Browser QA uses an injected fixture picker and disposable in-memory profile, validating real UI/API persistence of selected roots and grants without operating native windows. The native modal interaction itself and macOS/Linux sessions remain unverified by this Windows DOM-only automation environment.

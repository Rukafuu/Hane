## Integrity rules enforced

- Missing provider configuration or missing credentials produces an explicit API error; it never generates substitute LLM text.
- A provider failure remains a failed mission and a persisted audit event.
- Capability grants are a ceiling the runtime enforces for `workspace.read` and a promise for everything else. There is still no path from an LLM output to a file write, a shell command or a network call **on the machine this workspace is**: no route selects the box backend, so every mission today gets the workspace directory, whose executor only reads. The code that would write and run exists and is tested, but it only ever runs as `haneagent` inside a distribution that carries no Windows drive, no Windows PATH and no host name this tool can reach — which is the condition ADR-0007 makes the prerequisite of removing the click. A call naming a verb the chosen backend has no executor for is refused as `capability_not_available` before it reaches the sandbox, and is never offered to the model as a schema.
- File content given to a model is labelled untrusted data on every turn of the loop, a tool call that cannot be parsed is refused and audited instead of guessed, and nothing read is stored with the mission; a resume repeats the grant-bounded reads.
- The UI must present unavailable runtime capabilities as unavailable rather than inventing terminal or tool output.
- Machine detection is read-only: `hane machine status` and `GET /api/machine` never install, never configure a distribution, and never run the `wsl --install` hint they print. A distribution that exists is reported as `distro_present`, not as a box Hane can write to.
- Installation is a gate, not a side effect: `hane machine install` prints the argv it would run and touches nothing — not even the WSL probe — until the caller passes `--yes`. It installs a file the user names; Hane has no authority to fabricate a box image, and the hint `machine status` prints is still never run on the user's behalf.
- The box backend never assembles a shell line and never trusts its own absence: every verb is one `wsl.exe` call whose arguments after `--` are a list, a reachability probe must prove the distribution, the uid and the root before a non-zero exit is allowed to mean "this file is not here", and a command that ran with exit 1 is reported as an answer rather than converted into a refusal. A `run` with no machine-checkable command rule in the mission's grants spawns nothing at all.
- The box's boundary ships inside the image and a test watches it: `haneagent` never receives sudo, the human identity is created with `--disabled-password`, and the builder refuses to publish a tarball carrying `/etc/resolv.conf`, a kernel or initramfs, or a hashed `/etc/shadow` entry. What that does not buy is stated too: WSL2 keeps the agents off this disk, it does not defend against the Windows user who can always run `wsl -u root`, so the shared box is a boundary of *scope*, not a hardened sandbox against Lucas himself.

## Verification performed

The tool loop is covered against a scripted gateway: multi-turn reads and listings, sandbox denials that let the run continue, a call naming an ungranted or unknown tool (refused and audited, and still paid for), a five-ask executor bounded by a two-call tool budget whose refusal envelope the model itself receives, the turn guard, a provider-budget stop that lands in `needs_attention`, a run that is fail-closed with no root, no read grant, a vanished root or a provider that cannot take a turn, the inline-protocol fallback, and a resume that re-reads from disk. The CLI side (`test/cli.test.js`) is tested for the command line it prints, the exact argv it runs under `--yes`, the untranslated failure words, the usage error when no image is named, and a non-Windows platform that installs nothing. ## External end-to-end boundary

The repository tests use deliberately isolated provider doubles only under
`test/`. A live provider call was not issued in this audit: it may consume a
user-owned credential or quota. The minimal remaining evidence gate is a
user-authorized, low-budget call with a configured provider, followed by
inspection of the resulting SQLite mission and SSE events.

## Team creation and first use (2026-10-11)

The UI reuses one Team editor, with direct creation, optional description/leadership, and in-place agent creation that preserves the Team draft. Team persistence does not authorize folders or tools and does not invoke inference. Saved membership is additive in the UI and SQLite store. The three-member sequential preset requires explicit distinct role bindings; the legacy standard preset remains available as an explicit choice and does not use Team identities. Conversation remains available with one member. Provider metadata in the UI is configuration availability, not proof that a credential or remote service works; runtime validation remains authoritative. Concurrent orchestration is not implemented by this refinement.

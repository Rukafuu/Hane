# Runtime honesty audit

Date: 2026-10-09, revised 2026-10-10 for structured capability scopes, the
sandbox seam, the executor's real tool loop, WSL machine detection and the gated
box install command. Scope:
the Node core, loopback API, and the active UI in `work/mission-ui-prototype`.
Test doubles remain confined to `test/`.

## Integrity rules enforced

- Missing provider configuration or missing credentials produces an explicit API error; it never generates substitute LLM text.
- A provider failure remains a failed mission and a persisted audit event.
- Capability grants are a ceiling the runtime enforces for `workspace.read` and a promise for everything else. There is still no path from an LLM output to file writes, shell, or network execution: a call naming a verb this backend has no executor for is refused as `capability_not_available` before it reaches the sandbox.
- File content given to a model is labelled untrusted data on every turn of the loop, a tool call that cannot be parsed is refused and audited instead of guessed, and nothing read is stored with the mission; a resume repeats the grant-bounded reads.
- The UI must present unavailable runtime capabilities as unavailable rather than inventing terminal or tool output.
- Machine detection is read-only: `hane machine status` and `GET /api/machine` never install, never configure a distribution, and never run the `wsl --install` hint they print. A distribution that exists is reported as `distro_present`, not as a box Hane can write to.
- Installation is a gate, not a side effect: `hane machine install` prints the argv it would run and touches nothing — not even the WSL probe — until the caller passes `--yes`. It installs a file the user names; Hane has no authority to fabricate a box image, and the hint `machine status` prints is still never run on the user's behalf.

## Verification performed

- `npm test`: 313 tests passed in the exported candidate tree for this slice (the tree this commit publishes, with another session's uncommitted work absent), including persistence, SSE, provider retry, an in-flight cancellation integration test, the workspace containment suite (absolute paths, `..`, symlink escape, scope-escaping grants, deny-list case folding, credential-store paths, size cap, tool budget, denied-read auditing), the ingress grammar for command and host scopes, and the sandbox parity suite — which asserts the seam returns the same bytes and the same refusal token as the tools it replaced, and that a verb with no executor answers a refusal instead of throwing. The tool loop is covered against a scripted gateway: multi-turn reads and listings, sandbox denials that let the run continue, a call naming an ungranted or unknown tool (refused and audited, and still paid for), a five-ask executor bounded by a two-call tool budget whose refusal envelope the model itself receives, the turn guard, a provider-budget stop that lands in `needs_attention`, a run that is fail-closed with no root, no read grant, a vanished root or a provider that cannot take a turn, the inline-protocol fallback, and a resume that re-reads from disk. The router's refusals have their own unit suite (`test/tool-router.test.js`). The machine probe has one too (`test/machine-detect.test.js`, 13 tests): UTF-16LE and UTF-8 payloads, the no-distro answer, a failed listing that keeps the localized text verbatim, stderr that must not become a distro name, a present distro that is reported as unconfigured, a probe whose `--version` fails, and a non-Windows platform that spawns nothing; the CLI prints the report and the hint without running it, and `GET /api/machine` is tested for probe-once, for the no-probe answer, and for a throwing probe that degrades to a stated failure instead of a `500`. The tool budget is covered at both ingresses: a non-positive `--max-tool-calls`/`maxToolCalls` is refused before any provider call, and an `approve` that raises a spent budget is tested end-to-end over HTTP — the first round reads one file and runs out, the resume warns, and the raised budget lets the next round read again and audit the missing path as `tool_denied`. The provider budget is likewise covered at both ingresses, with the new default (ten, because a loop turn is a real call) asserted from the CLI and over HTTP. Installing a box has its own suite (`test/machine-install.test.js`, 13 tests): the argv is a list, so a path carrying spaces or `&&` stays one argument; the pre-`--yes` preview spawns nothing and does not even probe; a missing image, a directory or a wrongly-extended file is caught before the runtime is asked; `--yes` without WSL is refused without running an installer; a non-zero `wsl.exe` keeps its localized UTF-16LE words; and an unstartable `wsl.exe` is reported as missing rather than as a failed install. The CLI side (`test/cli.test.js`) is tested for the command line it prints, the exact argv it runs under `--yes`, the untranslated failure words, the usage error when no image is named, and a non-Windows platform that installs nothing.
- The probe was also run against the real machine, not only against doubles: `wsl.exe -l --quiet` exits non-zero with a localized "no installed distributions" message and an empty stdout on `--quiet`, `--version` answers `2.7.14.0`, and the whole output is UTF-16LE with a BOM — the three facts `src/machine/detect.js` is written around. Its answer here is `available: true, reason: "no_distro"`.
- `npm run check` over every source, bin and test file.
- `npm run build` and `npm run test:sites` in `work/mission-ui-prototype`.
- HTTP contract probed against a live `hane serve --workspace <dir>` on loopback: `GET /api/workspace` reported the resolved root, a `workspace/**` scope returned the glob refusal, an absolute or `..` scope returned the relative-path refusal, a missing root returned `Workspace root "..." does not exist.`, and a well-formed read grant reached provider resolution — the last gate before execution.
- The UI module was exercised by its own unit tests (`npm run test:sites` in the exported candidate tree: 24 passed, including the check that sends the composer's default scopes through the core's own ingress grammar, so a chip can no longer produce a `400`). Its consumer wiring was then driven in headless Chrome over CDP against a persisted fixture mission: the composer sends `scope: "."`, the chips stay disabled without a server root, the panel shows the real root, grants and `used/max` tool budget, the timeline renders the audited reads and refusals with their pt-BR reasons, and a `400` from the API appears in the composer's alert instead of being swallowed. Every slice since is committed from a candidate tree exported and verified on its own (`npm run verify`, and the prototype build and tests there), so what landed is what was checked — not a worktree carrying another session's uncommitted work.

## External end-to-end boundary

The repository tests use deliberately isolated provider doubles only under
`test/`. A live provider call was not issued in this audit: it may consume a
user-owned credential or quota. The minimal remaining evidence gate is a
user-authorized, low-budget call with a configured provider, followed by
inspection of the resulting SQLite mission and SSE events.
